## 结论

backend r29 / LuCI r12 已通过本地回归、OpenWrt 25.12.5 与 24.10.7 官方 SDK
构建、两套隔离 QEMU 中从 r28 原位升级，以及 Cudy TR3000 v1 + U30 Pro 的最终
只读部署验证。r29 修复了真实嵌套设备快照在稳定性采样器中的适配器解析问题；真机
`probe` 和单次脱敏采样均通过。

本次没有执行 `power_supply_mode` 写入。实机验证时 U30 是路由器的默认互联网出口，
不满足“备用设备/备用链路”校准前提。生产 capability、全局写开关、电源直供写开关
和智能充电开关均保持关闭。

## 实机写校准门槛

验证时默认路由为 `1.1.1.1 via 192.168.0.1 dev eth2`，即 U30 是当前主上网链路。
因此以下项目没有执行，也不能由只读结果推断成功：

1. `zte-u30-power-calibrate execute I_AM_ON_SPARE_U30` 的真实往返写入与原模式恢复。
2. 写入过程中 `eth2`、默认路由和 USB 数据链路连续性的硬件验证。
3. 开放 `power_supply_write` capability、启用智能充电及人工故障恢复演练。
4. 校准完成后的连续 72 小时稳定性采样。

必须先给路由器提供独立的默认 WAN，或把 U30 和插件迁移到备用路由器/备用 U30
台架。满足该条件后才能执行写校准；校准前不会发布声称智能充电已实机完成的正式版。
