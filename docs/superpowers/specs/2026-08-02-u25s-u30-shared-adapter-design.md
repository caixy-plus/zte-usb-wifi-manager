# U25S/U30 Pro 共用适配设计

日期：2026-08-02

## 目标

将现有 U25S 专用 OpenWrt 管理插件扩展为 U25S/U30 Pro 共用的中兴随身 WiFi
控制台，并连续完成三个交付阶段：U30 Pro 只读管理、日常写操作及回读、打包部署与
稳定性验收。智能充放电不恢复为产品目标。

## 已验证事实

- Cudy TR3000 v1 / OpenWrt 25.12.5 将 U30 Pro 枚举为 USB `19d2:1354`，产品名
  `U30 Pro`，网络接口为 CDC-NCM；安装 `kmod-usb-net-cdc-ncm` 后生成 `eth2`。
- U30 WebUI 基础配置标识 `DEVICE_MODEL:"U30Air"`、`DEVICE:"ufi/mu3351"`，
  仍使用 `/goform/goform_get_cmd_process` 和 `/goform/goform_set_cmd_process`。
- U30 拒绝当前插件的 HTTP 请求。使用 HTTPS、`Referer: https://192.168.0.1/`
  和 `isTest=false` 后，匿名只读请求成功返回现有 U25S 字段，包括 modem 状态、
  网络类型、信号和电量。
- U30 原生页面包含移动网络、Wi-Fi、客户端、流量、短信、SIM、诊断、重启、关机、
  供电和电池保护入口；具体写参数仍须按静态资源和受控实机回读逐项确认。

## 方案选择

### 方案 A：在 U25S 适配器内增加条件分支

改动最少，但协议、型号和能力条件会散落在 HTTP、会话、字段和动作代码中，后续增加
中兴设备时容易产生不可审计的隐式兼容。

### 方案 B：共用 goform 核心与显式设备配置档（采用）

提取传输协议、Referer、登录要求、USB ID、型号别名和能力为设备配置档；读取标准化、
动作语义、队列和 LuCI 保持共用。只有确有差异的字段或动作映射进入设备配置档。
该方案复用现有实现，同时让每项生产能力仍可独立校准和关闭。

### 方案 C：复制完整 U30 适配器

隔离最强，但会复制大量相同 goform、解析和安全代码，修复需要双份维护，不采用。

## 架构

### 设备发现

daemon 从 `/sys/bus/usb/devices` 读取 VID、PID 和产品名，只接受白名单设备：

- U25S/MU5650：保留现有配置档。
- U30 Pro `19d2:1354`：选择 U30 配置档。

无法唯一识别时返回 `unsupported_device`，不得回退为 U25S 或开放写能力。状态快照和
capabilities 必须报告实际配置档的 adapter ID、产品名和传输协议。

### goform 传输

HTTP 层接收经过验证的 `scheme` 与 `host`，只允许 `http` 或 `https`。Referer 从同一
origin 生成，禁止 URL 参数注入。U30 配置档固定使用 HTTPS；目标自签名证书仅在显式
设备配置档下允许 curl 的受限证书豁免，并在诊断状态标明 `tls_verification`。

匿名读取优先遵循设备配置。若接口返回认证错误，再进入现有凭据/会话流程；不得因
U30 当前匿名读取成功而删除 U25S 登录支持。Cookie 文件继续使用 `0600` 权限。

### 数据标准化

现有 U25S 字段白名单作为共享基线。每个读取模块将 U30 实机响应保存为去标识 fixture，
比较字段存在性、类型和枚举，再决定复用或增加覆盖映射。唯一标识、电话号码、短信正文
和 Wi-Fi 密码不得进入主快照、日志或仓库。

### 写操作

LuCI、ubus schema、参数验证、动作队列和状态跟踪保持不变。配置档只负责把语义动作映射
到经核实的 goform ID 与参数。每项动作必须同时满足：静态设备能力、全局 UCI 写门、
独立功能 UCI 门、参数校验和操作后回读。

重启、关机、SIM 切换、流量清零和短信删除继续使用独立确认及独立能力门。一次只校准
一个动作；任何未知、超时或回读不一致均返回失败，不自动重试破坏性写操作。

## 三阶段交付

### 阶段 1：U30 Pro 只读管理

- 增加 U30 USB 识别、HTTPS origin 与安全 Referer。
- 复用并校准总览、移动网络、SIM、电池、设备、Wi-Fi、客户端、流量和短信读取。
- LuCI 显示真实 U30 型号与 capability，不再硬编码 U25S。
- 包依赖加入 CDC-NCM；U25S 的 CDC-ECM 路径不得回归。
- 在模拟器、本地测试、双 SDK、双 QEMU 和 Cudy/U30 只读实机上验证。

完成条件：daemon 状态为 `ok`，快照持续更新，所有显示字段来自 U30，所有写能力仍关闭。

### 阶段 2：日常写操作与回读

- 按原生静态资源和受控请求依次接入 APN、连接模式、Wi-Fi、流量计划/清零、短信发送/
  删除/已读、SIM 切换、重启和关机。
- 每项动作覆盖成功、拒绝、认证过期、超时和回读不一致。
- 只有完成实机成功与失败路径校准的动作才将对应 U30 静态 capability 置 1；各功能 UCI
  门默认仍为 0，由管理员逐项启用。

完成条件：首版能力矩阵中不再存在声称可用但无实机证据的动作；未完成的高级功能保持
`native_console_only` 或 `not_implemented`。

### 阶段 3：打包部署与稳定性

- 升级 backend/LuCI 包版本，构建 OpenWrt 25.12 APK 与 24.10 IPK。
- 验证全新安装、原位升级、配置保留、驱动依赖、重启、USB 重插、设备重启和卸载。
- 在 Cudy 上部署候选版本，USB 为主上联、无线为备用，不改变 OpenClash、LAN 和防火墙。
- 运行加速故障注入和真实 72 小时稳定性采样；检查快照新鲜度、RSS、文件句柄、日志、
  动作结果限额和闪存写入。
- 更新能力矩阵、安装文档、SDK/QEMU/实机证据并提交推送。

完成条件：自动化、SDK、QEMU、Cudy/U30 实机和 72 小时门禁全部通过；否则发布状态保持
候选版并准确记录未通过项目。

## 错误处理与安全

- HTTP 被 U30 拒绝时报告 `transport_not_supported`，不得累积为模糊离线。
- TLS、认证、API、字段缺失和网络失败使用不同错误码，保留最后可信快照并退避。
- 无法确定设备配置档、写结果或当前状态时保持现状，绝不主动关机、切 SIM 或重置流量。
- 诊断与 fixture 必须经过敏感信息扫描；凭据和会话材料不写入进程参数、ubus 响应或 git。

## 测试策略

- 每个行为先写失败测试，再实现最小代码。
- 模拟器分别提供 U25S HTTP 与 U30 HTTPS profile，覆盖成功和故障响应。
- Shell 单元/行为测试覆盖设备选择、URL/Referer、证书策略、字段标准化、能力门和回读。
- LuCI 测试覆盖型号显示、错误横幅、独立确认和不可交叉授权。
- 双 SDK/QEMU 验证包生命周期；真实 Cudy/U30 只承担最终只读、受控写和稳定性验收。

## 非目标

- 不恢复基于电量自动切断 USB 的充放电策略。
- 不复制 OpenWrt 已有的 DHCP、防火墙、端口转发或 OpenClash 管理。
- 不在未验证前开放固件更新、恢复出厂、备份恢复或设备密码修改。
